## 一、项目概述

ACT-R Harness 是一个**神经符号运行时系统**，采用 Python + C# 双语言架构，通过 gRPC 协议通信：

| 组件 | 语言 | 职责 |
|---|---|---|
| `shared/proto` | — | gRPC 共享合约（两端共用） |
| `shared/ruleset/lab.yml` | — | 程序性规则集（当前演示场景） |
| `python/src/actr_harness` | Python | 声明性记忆、程序性记忆、神经核心 gRPC 服务 |
| `python/tests` | Python | 神经核心条件评估与动作解码的单元测试 |
| `Dotnet/src/Harness.Core` | C# | 步进循环、模块注册、gRPC 客户端、核心模块 |
| `Dotnet/src/Harness.Codebase` | C# | 代码导航模块（文件探索、代码视窗） |
| `Dotnet/src/Harness.Host` | C# | 可执行宿主，负责服务组装和 epoch/step 驱动 |

### 运行时协作流程

```
C# Host
  │
  ├─① 从各模块收集 buffer 状态
  ├─② 向 Python 程序性记忆请求所有规则条件
  ├─③ 向 Python 神经核心查询哪些规则满足
  ├─④ 向 Python 程序性记忆选择一条规则
  ├─⑤ 向 Python 神经核心解码该规则动作 → BufferOperation 列表
  ├─⑥ 将操作应用到本地模块
  └─⑦ 记录步进追踪，继续直到终止
```

## 二、当前阶段目标

**本阶段目标：端对端跑通 `lab.yml` 中的活跃程序性规则。**

最小演示需满足：

- Python 提供声明性记忆、程序性记忆、神经核心的 gRPC 服务
- C# 宿主持有运行时 buffer/模块，执行解码操作，驱动步进循环
- 宿主从一个预置目标出发，运行至完成或耗尽，并输出日志和简单报告

---

## 三、当前 `lab.yml` 活跃规则

共三条规则，构成一个小型代码库导航循环：

| 规则 | 触发条件 | 动作 |
|---|---|---|
| `rule-init` | `intention.current_goal.slots.status == "start"` | 查询声明性记忆，将 goal status 改为 `memory_queried` |
| `rule-memory-hit` | status 为 `memory_queried` 且有 chunk 被检索到 | 生成注意力标签，可选打开文件，status 改为 `file_opened` |
| `rule-memory-miss` | status 为 `memory_queried` 且无 chunk 检索到 | 推入 `ExploreFileSystem` 子目标 |

> 文件中注释掉的文件探索/视窗规则属于**下一阶段**，本阶段不要求实现。

## 五、阻塞演示的具体缺口

### 缺口 1 — Python 程序性记忆未加载规则集

**文件：** `python/src/actr_harness/services/procedural_memory.py`

- `self.rules` 初始化后**从未被填充**
- 服务未加载 `shared/ruleset/lab.yml`，导致 `GetAllConditions` 返回空列表

**需要做：** 启动时加载 YAML，将规则转换为 `ProceduralCondition` 和 `NeuroAction` 对象。

---

### 缺口 2 — C# 宿主缺少必要模块注册

**文件：** `Dotnet/src/Harness.Core/Extensions/DependencyInjectionExtensions.cs`

- 目前只注册了 `DeclarativeMemoryModule` 和 `IntentionModule`
- 活跃规则还需要 `FileExplorerModule` 和 `CodeViewportModule`

**需要做：** 在 Host/Core 路径中引用 `Harness.Codebase` 并注册缺失模块。

---

### 缺口 3 — `IEmbeddingService` 无实现

**文件：** `Dotnet/src/Harness.Abstractions/IEmbeddingService.cs`

- `FileExplorerModule` 依赖嵌入服务，但当前无任何实现

**需要做：** 为演示添加一个简单的本地实现（如基于词语重叠或返回固定向量），无需外部依赖。

---

### 缺口 4 — 步进循环无法多步运行

**文件：** `Dotnet/src/Harness.Core/HarnessCore.cs`

- `StepAsync()` 无条件返回 `true`，导致运行器每次只执行一步就停止

**文件：** `Dotnet/src/Harness.Host/HarnessRunner.cs`

- 循环逻辑依赖 `StepAsync()` 发出终止信号，但当前行为让每个 epoch 立即终止

**需要做：** 修改 `StepAsync()` 返回有意义的终止信息；将"无满足规则"作为正常结束状态处理。

---

### 缺口 5 — 配置文件存在无关配置项

**文件：** `Dotnet/src/Harness.Host/Program.cs` 和 `Options/GrpcClientsOptions.cs`

- 宿主配置中仍保留 `FrostpunkWorldAddress`，与当前演示路径无关

**需要做：** 清理或注释掉与演示无关的配置项。

---

### 缺口 6 — 无初始 intention goal 种子

- 没有任何组件在启动时注入 `{ id, query, status = "start" }` 这样的初始目标
- 导致 `rule-init` 没有可匹配的状态

**需要做：** 在第一步之前，在 intention 模块中种入初始目标。

---

### 缺口 7 — 缺少日志和报告管道

- 目前没有可供其他开发者在不使用调试器的情况下检查运行过程的输出

**需要做：** 添加结构化步进日志和报告文件输出。

---

## 六、任务工作流（推荐并行分工）

### 任务 1：Python 服务对齐

**目标：** 让程序性记忆服务真正能提供当前规则集。

- [ ] 启动时加载 `shared/ruleset/lab.yml`
- [ ] 将 YAML 规则转换为 `ProceduralCondition` 和 `NeuroAction` 对象
- [ ] 为每条规则设置初始稳定效用值
- [ ] 添加小型单元测试，验证三条活跃规则被正确加载

---

### 任务 2：C# 宿主模块注册

**目标：** 注册活跃规则所需的全部模块。

- [ ] 在 Host/Core 路径中引用 `Harness.Codebase`
- [ ] 注册 `FileExplorerModule` 和 `CodeViewportModule`
- [ ] 添加最小化的 `IEmbeddingService` 实现（本地确定性即可）

---

### 任务 3：步进循环与终止逻辑

**目标：** 让宿主能运行多步并在正确时机停止。

- [ ] 修改 `HarnessCore.StepAsync()` 返回有意义的终止信息
- [ ] 将"无满足规则"处理为正常结束状态，而非未处理失败
- [ ] 在第一步之前种入初始目标
- [ ] 明确定义首次演示的停止条件：
  - 无可用规则
  - 达到最大步数
  - 活跃目标达到终止状态

---

### 任务 4：日志与报告

**目标：** 让每次运行结果对其他开发者可检查。

- [ ] 每步结构化日志，包含：

  - 满足条件的规则 ID 列表
  - 被选中的规则 ID
  - 解码的操作列表
  - 步骤前后的 buffer 状态
  - 错误信息和停止原因
- [ ] 保存运行报告文件：
  - `artifacts/runs/<timestamp>/trace.jsonl`
  - `artifacts/runs/<timestamp>/summary.md`

---

### 任务 5：演示打包

**目标：** 让新加入的开发者能轻松复现演示。

- [ ] 提供真实可用的 `appsettings.json` 示例

## 七、推荐执行顺序（单人顺序开发最短路径）

```
1. 加载规则到 Python 程序性记忆
      ↓
2. 注册缺失的 C# 模块 + 添加最小嵌入服务
      ↓
3. 种入初始目标 + 修复循环终止逻辑
      ↓
4. 添加日志/报告输出
      ↓
5. 添加一个端对端冒烟测试或可复现的手动演示脚本
```
